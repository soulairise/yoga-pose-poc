## 1. 후보를 어떻게 늘어놓았는가

흔한 실수는 **한 회사의 대·중·소 세 등급**을 후보로 놓는 것입니다.
그러면 표에 나타나는 것은 **크기가 만드는 차이뿐**이고, 큰 것이 정확하고 느리다는
**재 보기 전에도 알던 결론**이 나옵니다.

그래서 **성격이 갈리게** 놓았습니다. 갈리는 축 셋입니다.

| 축 | 이 축이 갈리면 표에 나타나는 것 |
|---|---|
| **실행 위치** | 자료가 어디까지 나가는가 |
| **만들어진 목적** | 전용 모델과 범용 모델 중 어느 쪽이 이 일에 맞는가 |
| **결과의 형태** | 점수만 나오는가, 검토에 쓸 근거까지 나오는가 |

## 3. ★ 제외 조건을 점수와 섞지 않았습니다

**후보를 재기 전에** 두 가지를 확인해 걸러냈습니다.

### ① 자료가 어디까지 나가는가

회원의 **몸이 찍힌 영상**입니다. 외부 서비스로 보낼 수 없습니다.
→ **클라우드 자세 추정 API 후보는 성능과 무관하게 여기서 제외**했습니다.
   (점수를 매겨 본 뒤 감점하지 않았습니다.)

### ② 라이선스가 그 용도를 허용하는가

**후보 B(YOLO11-pose)는 AGPL-3.0**입니다.

| 쓰임 | 가능 여부 |
|---|---|
| 수업·연구에서 돌려 보기 | 가능 |
| **소울라이즈 동아리 앱 / 학과 도구로 배포** | **소스 공개 의무가 걸림** |

이 PoC는 **회원이 쓰는 도구로 이어지는 것을 전제**합니다.
→ 그래서 **B는 배포 시나리오에서 제외**하고, **비교 실험용으로만** 돌렸습니다.

> ### 순서가 결론을 바꿉니다
>
> ```
> ❌ 점수부터 매기면              ✅ 조건으로 먼저 걸러내면
>    1위 클라우드 API (정확도 최고)    클라우드 API → 자료 반출로 제외
>    2위 YOLO-pose                    YOLO-pose   → AGPL로 배포 제외
>    3위 MediaPipe                    MediaPipe   → 선택
>    → "회원 영상이 외부로 나간다"가   → 쓸 수 없는 후보가
>       각주로 밀림                       1위에 오르지 않음
> ```
>
> 감점 항목으로 다루면 **다른 항목이 높을 때 그 후보가 다시 올라옵니다.**

## 4. 최종 선택: MediaPipe Pose Landmarker

### 고른 이유 넷

**① 실행 위치가 조건을 만족합니다.**
온디바이스로 돌아 회원 영상이 기기 밖으로 나가지 않습니다. 이 업무에서는 **양보할 수 없는 조건**입니다.

**② 라이선스가 배포까지 열려 있습니다.**
Apache 2.0이라 나중에 동아리 앱에 넣어도 조건이 걸리지 않습니다. **B와 갈린 결정적 지점입니다.**

**③ 결과의 형태 — 관절별 신뢰도를 함께 줍니다.**
이 PoC에서 가장 중요한 항목입니다. 다리가 화면 밖이거나 가려져도 자세 추정 모델은
**좌표를 내놓습니다.** 대신 신뢰도를 낮게 붙여 보냅니다.
그 값을 읽지 않으면 **없는 다리의 무릎 각도가 계산되고, 오류 메시지도 없이 숫자가 나옵니다.**
→ 신뢰도를 관절 단위로 주는 것이 **판정을 걸러 낼 수 있게** 해 줍니다.

**④ 부피가 작아 반복 실험이 쌉니다.**
모델 파일 9.4MB. 값을 바꿔 가며 여러 번 돌려야 하는 PoC 단계에 맞습니다.

### 고르지 않은 이유

| 후보 | 왜 안 골랐나 |
|---|---|
| **B. YOLO11-pose** | **AGPL-3.0.** 성능이 아니라 **조건**에서 걸렸습니다. 배포 계획이 없다면 다시 후보가 됩니다 |
| **C. 기준선(사람)** | 후보에서 뺀 것이 아니라 **비교 대상으로 남겨** 두었습니다. → `docs/03_검증결과.md` |

> **기준선을 후보에 넣지 않으면 새로 만든 것이 쓸 만한지 판단할 근거가 없습니다.**
> 기준선이 이기면 결론은 "AI가 쓸모없다"가 아니라 **"이 업무에는 지금 방식이 낫다"**이고, 그것도 결과입니다.

## 5. 모델 안에서의 선택 — 크기는 마지막에 봅니다

MediaPipe는 `lite / full / heavy` 세 판본이 있습니다. **이건 "크기" 축이라 후보 구성에는 쓰지 않았고**,
모델 종류를 정한 다음에 골랐습니다.

- 선택: **`pose_landmarker_full`** (9.4MB)
- 이유: 측면 촬영에서 다리 관절이 가려지는 구간이 있어 `lite`는 신뢰도가 더 자주 떨어집니다.
  `heavy`는 처리 시간이 늘어나는데, 이 PoC의 성공 기준(S3, 실시간보다 빠를 것)에서
  `full`로 이미 만족하므로 더 키울 이유가 없습니다.
